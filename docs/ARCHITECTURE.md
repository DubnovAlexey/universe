# 🏛 Архитектура и техническое устройство UNIVERSE (v2.5)

## 1. Назначение и архитектурный обзор

**UNIVERSE (Нейроверс)** — интерактивная полноэкранная научно-художественная аудиовизуальная инсталляция и полиглот-витрина («Из Нуля в Ноль», 108-секундный непрерывный цикл), разработанная **Алексеем Дубновым (`DubnovAlexey`)** для демонстрации на **GitHub Pages**.

Проект объединяет три оптики над общей итоговой геометрией частиц. Физический provider выполняется до художественных целей; Canvas читает итоговые particle-объекты, NEXUS — квантование их координат, `SceneBufferSoA` — публикацию этой же геометрии. Это общий конвейер данных, а не один непрерывный блок памяти для всех языков:
1. **`ILLUSION` (Космическая оптика):** нестабильные дышащие кольца светового эха по мотивам цефеиды `RS Puppis`, спиральные пылевые рукава и каньоны поглощения света (`M31` / `NGC 3169`), 7-оболочечная корона «Кошачьего глаза» (`NGC 6543`) и аккреционный диск Чёрной дыры.
2. **`NEXUS` (Когнитивная топология):** двухполушарная нейронная сеть поверх 5 встречных кеплеровских колец с тремя классами рёбер (`Class A: MST Trunks`, `Class B: Gabriel Bridges`, `Class C: Murray Dendrites`) и кометами синаптических импульсов.
3. **`X-RAY / TRUTH` (Инженерная изнанка):** интерактивная мембрана преломления `BREACH LENS`, глубинная суб-квантовая сеть `Z4` («обратная сторона Вселенной»), векторы скоростей и парящие бесконтурные выноски узлов.

## 3. Контракт памяти `SceneBufferSoA`, 8-польный `NaN-Guard` и `ResourceLedger`

* Все координаты и скорости активных частиц синхронизируются в плоском буфере `SceneBufferSoA` (`frontend/src/core/sceneBuffer.ts`) с 24-байтным заголовком `Little-Endian` (`magic = 0x53564E55`, `schemaVersion = 2`, `flags`, `tick`, `count`, `seed = 104729`, `digest`).
* Метод `syncEntityFromParticle` проверяет на конечность (`Number.isFinite`) и учитывает в `nanGuardTriggeredCount` все 8 числовых полей (`x, y, z, vx, vy, vz, depthZ, energy`).
* Книга учёта ресурсов `ResourceLedger` контролирует все 5 категорий (`buffers, textures, audioNodes, listeners, workers`) и диагностирует `underflowCount` и `disposerErrors`.

## 4. Реализованный контракт Rust/WASM и TypeScript

`frontend/public/wasm/physics_engine.wasm` — реальный raw WASM-модуль размером около `54 КиБ`, ABI v1, без imports и JS glue. Оба provider используют один порядок инициализации PRNG, фазы/частоты `f32[1024]` и массивы позиций/скоростей `f32[3072]`; в последних физически рассчитываются первые 64 контрольные орбиты. Шаг, накопленное время и метрики передаются как `f64`; `step_verlet_nbody` возвращает статус `1`/`0`, проверяемый host до readback.

Положительный шаг ограничен `0.05 с` и разбивается на `ceil(dt / 0.004)` равных подшагов; `dt <= 0` и нулевое число активных объектов не продвигают симуляцию. Время накапливается по выполненным подшагам. Модель Курамото рассчитывает фазы активных частиц для дыхания и геометрии тройной структуры позднего GENESIS. Velocity Verlet интегрирует отдельные 64 орбиты в статическом потенциале Пламмера (`GM = 4900`, `ε² = 64`); `ΔE/E₀` относится к ним, а не ко всей художественной сцене. Полная N-body динамика сцены не реализована.

Позднее подключение WASM загружает актуальные TS-фазы, частоты, контрольные позиции/скорости, начальную энергию и накопленное время через `commit_uploaded_state`. Restart/seed/count переинициализируют native-provider по текущему состоянию. После валидного шага Rust зеркала TS обновляются целиком; при trap или неверном результате fallback продолжает от последнего принятого состояния. Отклонённый upload требует от host отказаться от provider: live-массивы WASM не являются транзакционной staging-памятью.

Актуальный набор содержит 48 модульных проверок: 27 TS, 8 Python и 13 native Rust, плюс 5 интеграций реального WASM. Последние включают 600 смешанных шагов, memory growth/count, reset/seed/позднее подключение, trap/ABI/указатели/отклонённый шаг и цепочку Rust-фаза → видимые координаты → граф/SoA. Финальный `verify:all`, Astro build и Pages artifact прошли без warning/error; `npm audit` — 0. Актуальный выборочный desktop/mobile smoke подтвердил карточку, доступные действия, клавиатурный фокус, канонические aria-label, паузу и supplementary глифы. Точные результаты и открытые границы — [QA_STATUS.md](QA_STATUS.md). Предыдущий выборочный smoke фундамента подтвердил default native, ACT_D, второй цикл и TS fallback; непрерывные 108 секунд, Safari/iOS, звук и p50/p95 остаются отдельной проверкой.

## 5. Реализованный V1 и исправления QA

`visualSignals.ts` публикует один замороженный снимок фазы, времени, паузы/reduced motion, аудиополос, heartbeat, Kuramoto и stress на существующий кадр renderer. Водопад, Canvas-одометр и DOM-визитка читают общий снимок. `glyphGrammar.ts` хранит полные Unicode code point и пять фазовых профилей; браузерный фильтр неподдерживаемых глифов выбирает ASCII fallback, без загрузки тяжёлого шрифта.

`glyphHover.ts` выполняет три roll-шага `160–180 мс` и canonical dwell `280–320 мс`, локальное свечение/смещение и восстановление точного текста при завершении, уходе курсора/blur, паузе и reduced motion. Доступное имя кнопки стабильно, автономный одометр сохраняет `18–26 Гц`. После первого полного круга фоновая карточка за 12 секунд активного времени C²-плавно поднимается в пределах свободного места: расстояние зависит от высоты карточки и свободного места сверху, с более сдержанным подъёмом на узком экране; `.ambient-loop` имеет opacity `0.60`, мягкую глубокую тень и прозрачную радиальную подложку. Пауза замораживает ход, reduced motion задаёт статичное положение.

Промежуточный изгиб графа теперь учитывает seed только у `AXON_TRUNK`, как обе реализации builders; truth reveal линзы получает текущее `simulationTimeSec`. Общий decimal-контракт TS/Python — `floor(v * scale + 0.5) / scale`, включая отрицательные ties к `+∞`. Полный transport fixture24 и fixture6 не доказывают паритет всех графов: sampling использует `max(1, floor(Nactive / 28))` и начинается при 56 активных узлах.

`npm run verify:repo` проверяет отслеживаемые исходники/fixtures и npm entry scripts до численных проверок и сборки. Скрипты остаются в `frontend/scripts/`, доступны из корня через npm wrappers. TS-типы сами по себе не обеспечивают компиляционную проверку Rust ABI; используются межъязыковые проверки реального модуля.
