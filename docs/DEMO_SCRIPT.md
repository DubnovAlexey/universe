# 🎬 Сценарий демонстрации и проверки UNIVERSE (v2.5)

Этот документ содержит краткий сценарий знакомства с проектом для двух аудиторий: **зрителей** (визуальный тур) и **системных архитекторов / CTO / преподавателей** (техническая проверка).

---

## 1. Визуальный тур (60 секунд)

1. **Автоматический старт (`01.VOID` -> `02.GENESIS`):**
   * Откройте страницу проекта на GitHub Pages (`https://dubnovalexey.github.io/universe/`) или локально (`http://localhost:4321/`).
   * С первой секунды запускается сцена рождения Вселенной из Точки Нуля с живыми дышащими кольцами светового эха по мотивам цефеиды `RS Кормы`. Любой клик или касание экрана (на компьютере или смартфоне) включает непрерывный космический саундтрек `cosmic_ambient.mp3`.
2. **Интерактивная линза `BREACH LENS` (зажатие кнопки мыши или клавиша `Space`):**
   * Нажмите и удерживайте левую кнопку мыши в любой точке космоса и поводите курсором.
   * Вокруг курсора раскроется упругая мембрана преломления света, обнажающая геодезическую сетку рентгена и глубинный суб-квантовый слой `Z4` («обратную сторону Вселенной»).
3. **Прямой переход к финалу и визитке (`05.SINGULARITY`):**
   * Нажмите кнопку **`05.SINGULARITY`** в нижней панели (или дождитесь 79-й секунды цикла).
   * Наблюдайте рождение короны «Кошачьего глаза» (`NGC 6543`) и Чёрной дыры, которая затем по спирали сожмётся в яркую микро-точку и без паузы раскроется в голографическую визитку **`DUBNOV ALEXEY`**.
4. **Переход в профиль GitHub и работа на фоне:**
   * В визитке (а также в правом нижнем углу экрана) доступны прямые кнопки перехода на главную страницу профиля **[ ↗ GITHUB PROFILE : DUBNOV ALEXEY ](https://github.com/DubnovAlexey)** и в репозиторий проекта **[ ↗ PROJECT REPOSITORY ](https://github.com/DubnovAlexey/universe)**.
   * Когда цикл пойдёт на следующий круг, визитка за 12 секунд активного времени плавно поднимется и останется поверх космоса с opacity `0.60`, мягкой тональной подложкой без внешнего box-shadow и глубокими тенями текста. Наведение или клавиатурный фокус усиливают видимость. Пауза замораживает подъём, reduced motion выбирает статичное положение.

## 2. Инженерный тур и команды проверки (61 модульная + 6 интеграционных WASM)

### Проверка телеметрии в реальном времени
* В правой колонке «Цифрового водопада» (`LAYER_02`, `LAYER_03`, `LAYER_04`) отображаются замеры времени кадра (`FPS / P95`), относительный дрейф энергии отдельного ансамбля из 64 контрольных орбит `Velocity Verlet` (`REF64 ΔE/E₀`), параметр синхронизации Курамото `r(t)`, число рёбер графа `NEXUS` (`MST`, `Gabriel`, `Murray`), выборочная оценка диаметра `EST. DIAMETER / PATH (BFS)`, 32-битный `State Digest`, все 8 модулей `IntegrationRegistry` и счётчики `ResourceLedger`. Короткое значение FPS не заменяет воспроизводимый бенчмарк.
* Нажатие кнопки **`🔬 X-RAY`** (или клавиши `5`) включает полноэкранный инженерный рентген с парящими выносками узлов (`ID#... [модуль]`).
* В текущей сборке Rust/WASM загружается асинхронно по умолчанию. После первого валидного native-шага появляется `WASM_ACTIVE`; `?wasm=0` позволяет сравнить TS fallback. Kuramoto влияет на дыхание и геометрию позднего GENESIS, а энергия `REF64` описывает отдельный консервативный ансамбль. Полной N-body симуляции всей сцены нет. WebGPU остаётся probe, NEXUS работает синхронно в TS, Python — офлайн/CI reference.

### Наведение и читаемость V1

На угловом блоке, кнопках фазовой шкалы, инструменте управления или статической строке визитки проверьте три различимых roll-шага по `160–180 мс` и удержание канонического текста `280–320 мс`. При уходе курсора/blur точный текст восстанавливается, доступное имя кнопки остаётся неизменным; у generic p/span канон доступен отдельно от `aria-hidden` декора; пауза и reduced motion останавливают декоративный ход. В центре визитки автономная строка сохраняет собственные `18–26 Гц`. Проверьте реальный перебор кириллицы в brand-card и точное восстановление русской строки. Переключение фазы/restart не должно сокращать roll/dwell: используется общий frameDtSec. Проверьте читаемость системных глифов и ASCII fallback на используемом устройстве.

### Команды автоматической проверки из терминала

    # 0. Проверка отслеживаемых исходников, fixtures и npm entry scripts
    npm run verify:repo

    # 1. CLI-проверка математического паритета Python-ядра (PRNG, пакет 'UNVS', граф NEXUS, оптика BREACH)
    python -B -m backend.main --verify

    # 2. Запуск 9 модульных тестов Python (unittest)
    python -B -m unittest discover -v

    # 3. Запуск 13 модульных тестов физического крейта Rust
    npm run test:rust

    # 4. Строгая проверка типов TypeScript во всём фронтенде
    npm --prefix frontend run typecheck

    # 5. Запуск набора регрессионных тестов фронтенда (39 инвариантов)
    npm --prefix frontend run test

    # 6. Сборка raw Rust/WASM ABI v1 и 6 интеграционных проверок реального бинарника
    npm run build:wasm
    npm run verify:wasm

    # 7. Сборка статического продакшен-бандла для GitHub Pages и проверка артефакта
    npm --prefix frontend run build
    npm run verify:pages-artifact

Для сборки нужны Node.js `>=22.23.4`, текущий Astro `7.4.2` по lock-файлу и Rust target `wasm32-unknown-unknown`. Общий сценарий `npm run verify:all` начинает с guard полноты репозитория и включает перечисленные проверки. Модульный итог — 61 (39 TS + 9 Python + 13 Rust), отдельно 6 интеграций WASM. WASM-интеграции проверяют скалярный шестипараметрический BREACH reference (10 752 f32-нормализованных образца при stress=0.25/time=0, допуск 2e-4 px; векторная Canvas-оптика остаётся TS), 600 смешанных шагов TS/Rust, memory growth/count, seed/reset/позднее подключение, fallback при trap/неверном ABI/указателях и влияние native-фазы на видимые координаты и их граф/SoA. Полный браузерный цикл, второй цикл, звук, узкий экран и Safari/iOS проверяются отдельно.

Предыдущий production smoke фундамента: default `WASM_ACTIVE`/`READY`, ручной переход к фазе 05 и ACT_D/имя, автоматический вход во второй цикл с сохранённой визиткой, TS fallback при `?wasm=0`, native на viewport `507×684` с открытыми метриками и видимым управлением. Warning/error в просмотренных запусках не зарегистрированы. Это выборочный smoke; непрерывный полный цикл, звук, Safari/iOS и p50/p95 этим не подтверждаются.


Финальный production `verify:all` под Node 22.23.4 прошёл 61 модульную и 6 WASM-проверок, typecheck, Astro/Pages; audit — 0. Выборочный desktop/mobile smoke подтвердил доступность действий без обрезки, паузу, кириллический доступный канон, supplementary глифы и BREACH open/close. Точные результаты 25.10 и открытые границы — [QA_STATUS.md](QA_STATUS.md). Проверьте desktop `1440×900` и compact `507×684`: карточка немного выше, мягкая тональная подложка без овального box-shadow, радиус 36 px, все кнопки доступны, горизонтального скролла нет. Сравните pause/hidden/reduced режимы: водопад и визитка получают общий кадр, не должны выполнять повторную холостую DOM-работу; resize обновляет layout.
